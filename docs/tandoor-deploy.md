# Tandoor Recipes: deploying on the cluster

This runbook covers the **net-new** [Tandoor Recipes](https://github.com/TandoorRecipes/recipes)
deployment under `kubernetes/apps/tandoor/`. It uses the
[`bjw-s` app-template](https://bjw-s-labs.github.io/helm-charts/) with **external Postgres
(CloudNativePG)**, reached at <https://tandoor.int.nerdbox.dev> (internal only).

Tandoor 2 runs the app + its **bundled nginx** in a **single container**
(`ghcr.io/tandoorrecipes/recipes`); only Postgres is external. It keeps two kinds of state:

- **PostgreSQL** (`tandoor-postgres`, PG17) — all recipes, ingredients, meal plans, shopping
  lists, users. Backed up nightly via CNPG barman → RustFS (`s3://postgres-backups/`, server
  name `tandoor-postgres`, cron `0 0 7 * * *`).
- **Media** (`tandoor-media`, local-path) — user-uploaded recipe images + imported files at
  `/opt/recipes/mediafiles`. **Non-rebuildable**, so it's backed up nightly by **VolSync
  restic** → RustFS (`s3:.../volsync/tandoor`, cron `35 7 * * *`).

Static assets (`/opt/recipes/staticfiles`) are regenerated by `collectstatic` on every boot,
so they live on an `emptyDir`, not a PVC.

## Prerequisites (DNS)

- **DNS**: `tandoor.int.nerdbox.dev` → cluster ingress (like the other `*.int` hosts).

No NAS prerequisite — media is on a local-path PVC (restic-backed), not NFS.

## What's in `kubernetes/apps/tandoor/`

| File | Role |
|------|------|
| `namespace.yaml` | `tandoor` namespace. |
| `postgres-cluster.yaml` / `postgres-objectstore.yaml` / `postgres-scheduledbackup.yaml` | CNPG `tandoor-postgres` (PG17, 3 instances) + barman → RustFS + nightly backup. |
| `cnpg-rustfs-creds.sops.yaml` | RustFS S3 creds for barman. |
| `pvc.yaml` | local-path `tandoor-media` (RWO, uploads). |
| `tandoor-restic-secret.sops.yaml` / `replicationsource.yaml` | VolSync restic backup of `tandoor-media`. |
| `secret.sops.yaml` | `tandoor-secret`: Django `SECRET_KEY` + `SOCIALACCOUNT_PROVIDERS` (allauth OIDC JSON). |
| `helmrelease.yaml` | The app controller → Service `tandoor:8080`. |
| `ingress.yaml` | `tandoor.int.nerdbox.dev` (no forward-auth — Tandoor has its own login + OIDC). |

CNPG auto-generates the `tandoor-postgres-app` secret (key `password`) that the HelmRelease
consumes; the app connects to `tandoor-postgres-rw:5432`.

### Reverse-proxy notes

- The bundled nginx binds `TANDOOR_PORT: "8080"` (unprivileged); Service, Ingress, and probes
  all target 8080.
- Traefik terminates TLS and forwards HTTP, so Django is told the public origin is trusted via
  `CSRF_TRUSTED_ORIGINS: https://tandoor.int.nerdbox.dev` — **required**, or the login POST
  fails CSRF (`CSRF_TRUSTED_ORIGINS` defaults to `[]` and is not auto-populated).
- `ALLOWED_HOSTS: "*"` because kubelet probes hit the pod IP; the app is internal-only behind
  Traefik + OIDC.

## Deploy

1. Merge the PR to `main`, then `flux reconcile kustomization apps --with-source`
   (or wait for the interval).
2. Watch it come up:
   ```sh
   kubectl -n tandoor get pods,cluster,ingress
   ```
   Expect `tandoor-postgres-{1,2,3}` and `tandoor-*` (the app) all Ready. First boot runs DB
   migrations + `collectstatic`, so the startup probe has a generous window.
3. **First superuser** — Tandoor has no admin-from-env; create one once:
   ```sh
   kubectl -n tandoor exec -it deploy/tandoor -- python manage.py createsuperuser
   ```
   (Or complete the first-run setup in the web UI.) Log in at
   <https://tandoor.int.nerdbox.dev>.

### First-boot media ownership check (VolSync)

Confirm how Tandoor writes its media, because the VolSync mover must be able to read it:
```sh
kubectl -n tandoor exec deploy/tandoor -- ls -ln /opt/recipes/mediafiles
```
- Files owned by **uid 1000** → the `fsGroup: 1000` (HelmRelease) + mover
  `runAsUser/runAsGroup/fsGroup: 1000` (`replicationsource.yaml`) config is correct.
- Files **root-owned** → switch to privileged movers like gitea: add
  `volsync.backube/privileged-movers: "true"` to `namespace.yaml` and set the mover
  `runAsUser/runAsGroup/fsGroup: 0`.

## OAuth / OIDC (Authentik)

SSO is wired the same way as paperless (see `authentik-sso.md`). The Authentik side is fully
GitOps:

- Blueprint `kubernetes/apps/authentik/blueprints/tandoor-oauth2.yaml` — group `tandoor-users`,
  an OAuth2 provider (`client_id: tandoor`), the `tandoor` application, and a policy binding
  restricting access to `tandoor-users`.
- The client secret is one generated value stored in **two** SOPS secrets: `authentik-secret`
  → `TANDOOR_OAUTH2_CLIENT_SECRET` (injected into the worker, read by the blueprint via `!Env`)
  and `tandoor-secret` → `SOCIALACCOUNT_PROVIDERS` (the allauth provider JSON, with the same
  secret inline).
- Tandoor reads OIDC from env (`SOCIAL_PROVIDERS` + `SOCIALACCOUNT_PROVIDERS`), the allauth
  callback being `/accounts/oidc/authentik/login/callback/` (registered in the blueprint).
  New SSO users auto-join the default space as regular users
  (`SOCIALACCOUNT_AUTO_SIGNUP` / `SOCIAL_DEFAULT_ACCESS` / `SOCIAL_DEFAULT_GROUP: user`).

To use it: add your Authentik user to the **tandoor-users** group, then click
**"Sign in with Authentik"** on the Tandoor login page. Local login stays enabled as a
fallback.

> **Admin via SSO:** Tandoor does not grant Django superuser from an OIDC claim, so the
> **bootstrap superuser** (from `createsuperuser`) remains the admin. Promote your SSO user in
> the Django admin if you want to run day-to-day as that identity.

## Rotating secrets

`SECRET_KEY`, the OIDC client secret, and the restic password were generated at deploy time.
To rotate the OIDC client secret, regenerate one value and update **both**
`authentik-secret` (`TANDOOR_OAUTH2_CLIENT_SECRET`) and `tandoor-secret`
(`SOCIALACCOUNT_PROVIDERS` JSON) — they must stay in sync. Edit encrypted files in place with
`sops <file>` (never run kustomize transformers over them).

## Recovery

- **Postgres** — restore the latest barman backup into a fresh CNPG cluster (see
  `backup-recovery.md`).
- **Media** — restore the `tandoor-media` PVC from the VolSync restic repo with a
  `ReplicationDestination` (see `backup-recovery.md`).

## Rollback

Net-new and self-contained: remove `- tandoor` from `kubernetes/apps/kustomization.yaml`
(Flux prunes the namespace) and revert the Authentik blueprint/secret/worker-env additions
(purely additive).
